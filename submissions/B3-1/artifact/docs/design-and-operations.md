# 설계와 운영 설명

## 네트워크 흐름 (REQ-011)

VPC는 실습 네트워크의 주소 공간과 격리 경계다. Public Subnet은 EC2가 놓이는 하위 주소 공간이며, 인터넷 접근은 이름으로 결정되는 것이 아니라 연결된 Route Table의 기본 경로와 IGW 연결로 결정된다.
외부 요청은 퍼블릭 IPv4와 IGW를 통해 EC2의 사설 인터페이스로 전달된다. Subnet의 Route Table은 응답 및 아웃바운드 목적지가 VPC 내부가 아니면 `0.0.0.0/0 → IGW`를 사용한다. 보안 그룹은 해당 트래픽을 허용해야 하며 서버가 실제 포트에서 듣고 있어야 한다.

## 포트와 권한의 역할 (REQ-012)

보안 그룹은 EC2 인터페이스의 네트워크 트래픽을 제어한다. IAM은 AWS API에서 누가 어떤 작업을 할 수 있는지 제어한다. HTTP 80은 원문의 공용 IP 검증용, HTTPS 443은 암호화 웹 접속과 인증서 검증용이다. SSH 22는 관리자 현재 IP /32만 허용한다. DB나 다른 관리 포트, 전체 포트 공개 규칙은 없다.
SSH와 DB를 전 세계에 공개하면 무차별 인증 시도와 취약점 탐색을 허용한다. 관리 접속은 출발지 제한이나 SSM을 사용하고 DB는 사설 네트워크와 애플리케이션 SG 소스로 제한하는 대안이 있다. 이 과제는 SSH 증명이 필수여서 /32 제한 SSH를 사용한다.
현재 AWS 관리형 로그인 역할은 실습 역할을 준비하기 위한 접근이다. 실제 프로비저닝은 `codyssey-b3-1-deployer`가 수행하며 EC2/VPC의 지정 작업과 시드니 리전, t3.micro 실행으로 제한한다. 실습 역할에는 IAM/S3/RDS/AdministratorAccess 권한이 없다. `Resource: *`인 네트워크 작업은 생성 전 ID를 알 수 없거나 목록 조회 작업이므로 사용하되 액션·리전 제한으로 범위를 줄였다. 다른 실습용 리소스까지 수정할 수 있는 잔여 범위는 존재한다.

## 외부 장애 점검 (REQ-013)

1. Route Table 연결, 기본 IGW 경로, IGW의 VPC 연결을 확인한다.
2. SG에서 실제 포트와 출발지 CIDR을 확인한다. SSH /32는 운영자 IP 변경 시 갱신해야 한다.
3. EC2 퍼블릭 IP와 DNS 결과를 확인한다. 자동 공용 IP는 stop/start 후 바뀔 수 있다.
4. 서버 프로세스, Docker 상태·로그, cloud-init 결과, 로컬 curl을 확인한다.

서버 내부 curl은 성공하고 외부 요청만 실패하면 먼저 경계 설정을 확인한다. 내부 요청도 실패하면 서버 준비 상태나 설정 문제를 조사한다. 원인 가설 하나를 세우고 관찰 결과로 확인한 뒤 해당 설정만 바꾼다.

## IAM 작업 실패 (REQ-014)

실패한 API 이름, 요청 리전·리소스·요청 조건과 오류를 수집한다. 실습 역할 정책뿐 아니라 SCP, permissions boundary, 세션 정책의 명시적 Deny를 확인한다. 필요한 단일 액션과 리소스 범위를 공식 서비스 권한 표에서 찾아 좁게 수정한다. AdministratorAccess로 덮어쓰지 않는다. IAM Allow가 있어도 SCP Deny를 우회할 수 없으며 관리형 프로젝트의 보호 규칙은 관리자 역할로도 무시할 수 없다.

## 인스턴스 2대 확장 가정 (REQ-015)

현재 단일 EC2는 용량 한계와 단일 장애 지점이다. 직접 공용 IP 접속은 두 서버로 균등 분배하지 않는다. 실제 확장 시 ALB를 앞단에 두고 target group의 /health 검사, 두 AZ의 인스턴스 또는 Auto Scaling Group, 공통 배포 이미지와 외부 상태 저장을 고려한다. ALB와 추가 인스턴스는 비용을 늘리므로 이 실습에서는 생성하지 않는다.

## 과금과 정리 (REQ-016)

EC2 실행 시간, CPU surplus credits, EBS 용량, 공용 IPv4, 네트워크 전송, NAT Gateway와 ALB 등이 과금 요인이다. 이 구성은 EC2 1대·8GiB EBS·자동 IPv4만 사용하며 T3는 standard credits로 추가 CPU 크레딧 비용을 피한다. Elastic IP/NAT/ALB/RDS를 생성하지 않는다.
예상 밖 비용은 AWS Settings Billing에서 서비스와 리전별 사용 내역을 보고 리소스 태그와 저장된 식별자를 대조한다. EC2를 stop하는 것만으로 EBS와 주소 비용이 없어지지 않으므로 terminated 상태, 루트 볼륨 삭제 및 잔여 리소스를 확인한다. IGW는 분리 후 삭제하고 Subnet/Route Table/SG 등 의존성을 제거한 뒤 VPC를 삭제한다. 청구 반영 지연 때문에 조회 직후 0을 단정하지 않는다.
