# 실행 증거의 출처와 재검증

발표 HTML의 터미널 모양 텍스트는 저장 로그를 설명하기 위한 표시다. 직접 실행 화면 캡처와 동일한 증거로 취급하지 않는다. 기존 `evidence/docker-ps.jpg`는 로그를 로컬 HTML에 표시한 캡처이므로 실행 증거에서 제외하고 기록만 보존한다.

## 두 실행을 구분한다

- 최초 실습: EC2 `i-00d9faeaebdfcbb1f`, 공용 IP `13.236.1.62`. 원본 로그와 실제 외부 브라우저 화면은 당시 기록이며 자원 정리를 완료했다.
- 증거 보강 재검증: EC2 `i-0cf8f875fa410d4b2`, 공용 IP `3.106.167.194`, 시드니 `ap-southeast-2`. 별도 생성 기록으로 관리한다. 최초 실행의 화면을 다시 찍은 것으로 소개하지 않는다.

## 직접 실행 증거

재검증의 AWS 공식 콘솔 화면과 AWS CloudShell에서 직접 실행한 명령 화면을 `evidence/recheck/`에 보관한다. CloudShell 계정 조회, EC2 ID·IP·상태 조회를 비교해 같은 계정과 인스턴스임을 대조한다. SSH 서버의 호스트 이름과 EC2 사설 주소도 연결한다.

원본 PTY 기록은 `.cast`, 명령·시각·종료 코드는 `.metadata.json`, 실제 출력 바이트는 `.txt`로 보관한다. 출력 내용을 재생성하지 않고 실제 프로세스에서 읽은 바이트와 경과 시간을 저장했다. SHA-256 목록은 보관 이후 파일 변경 확인용이며 AWS가 서명한 실행 증명은 아니다.

## 접근과 정리

재검증 캡처를 위한 CloudShell SSH는 사용자가 승인한 `15.134.86.41/32`와 임시 공개 키에 한정한다. 캡처 후 이 키와 규칙을 제거하고 이번 재검증 자원만 정리한다. 자격 증명 값과 개인 키는 산출물에 포함하지 않는다.

## 재검증 완료

2026-10-10 UTC 12:37에 실제 CloudShell SSH의 Docker Up과 내부 200 OK를 캡처했다. 외부 HTTPS는 CloudShell 및 사용자 컴퓨터에서 인증서 검증을 생략하지 않고 200 OK를 반환했다. 초기 부팅의 DNS 오류로 Docker 설치가 실패한 원본과 설치 재시도 기록도 보존했다.

임시 공개 키 등록·단일 /32 허용 제거를 완료했다. CloudShell의 임시 개인 키와 공개 키 파일도 제거했다. 재검증 EC2는 terminated, 실습 태그의 EBS·주소·VPC·IGW는 빈 목록이며, IAM 인라인 정책과 실습 역할 삭제도 성공했다. 이전 실행의 네트워크 ID와 현재 실행의 ID는 다르다.
