줄별 설명

  1. 1-14

    `useCallback`, `useContext`, `useEffect`, `useState`는 사용자 정보와 비동기 요청 상태를 관리하는 React 훅이다.

    Firestore의 `getDocs`, `addDoc`, `updateDoc`, `deleteDoc`가 조회와 CRUD 요청을 맡고, `collection`, `query`, `where`, `doc`는 대상 문서와 사용자별 조회 조건을 만든다.

    `Auth`와 `db`를 가져와 로그인 사용자와 Firebase 인스턴스를 이 훅의 데이터 경로에 연결한다.

  2. 16-21

    `useItems()`는 사용자별 기록 상태를 한곳에서 관리하는 커스텀 훅이다.

    `useContext(Auth)`에서 현재 `user`를 얻고, `items`에는 조회 결과, `busy`에는 요청 진행 여부를 둔다.

    `error`는 저장·삭제 실패, `loadError`는 최초 목록 조회 실패를 따로 보관해 화면에서 원인을 구분한다.

  3. 23-33

    `useEffect`는 인증 사용자 `user`가 바뀔 때마다 목록 조회를 다시 수행한다.

    `active`는 이전 사용자 요청이 늦게 끝나 새 사용자 화면을 덮지 못하도록 effect의 유효성을 표시한다.

    로그인 사용자가 없으면 기록과 조회 오류를 비우고 로딩을 끝낸 뒤 cleanup 함수를 반환해 이 effect를 무효화한다.

  4. 35-38

    새 사용자 조회를 시작할 때 기존 목록을 비워 다른 사용자의 기록이 잠시 보이지 않게 한다.

    `busy`를 켜고 `loadError`를 지운 뒤 `getDocs`로 `items` 컬렉션을 조회한다.

    `where("userId", "==", user.uid)` 조건이 현재 로그인 사용자 소유의 문서만 요청한다.

  5. 39-50

    조회가 완료되어도 `active`가 false면 이전 사용자 응답을 무시한다.

    각 Firestore 문서에서 `id`와 저장 필드를 합쳐 React가 쓸 기록 객체를 만든다.

    Timestamp의 `toDate()` 결과를 한국 날짜 문자열로 바꾸고 값이 없으면 `최근`을 표시한다.

    변환된 배열을 `setItems`에 넣어 Context를 소비하는 화면이 새 목록으로 다시 렌더링된다.

  6. 51-61

    조회 실패는 유효한 effect에서만 `loadError`에 기록해 목록 화면의 오류 상태로 전달한다.

    요청이 끝나면 여전히 현재 사용자 요청일 때만 `busy`를 끈다.

    effect가 정리되거나 `user`가 바뀌면 `active`를 false로 바꾸고, 의존성 배열 `[user]`가 재조회 시점을 결정한다.

  7. 63-79

    `save(data)`는 등록과 수정을 하나의 비동기 동작으로 제공하며 `useCallback`이 현재 `user`에 맞는 함수를 유지한다.

    로그인 사용자가 없으면 `error`에 안내를 저장하고 실패값 `false`를 반환해 페이지가 성공 화면으로 이동하지 않게 한다.

    요청을 시작할 때 진행 상태와 이전 오류를 갱신한 뒤 저장할 제목·내용·분류·사용자 ID·서버 시각을 `payload`에 모은다.

  8. 80-96

    `data.id`가 있으면 `updateDoc`으로 기존 문서를 갱신하고, 성공 뒤 같은 ID의 로컬 항목을 새 입력값으로 교체한다.

    수정된 항목의 `updated` 표시는 방금 갱신된 값으로 바뀐다.

    ID가 없으면 `addDoc`으로 새 문서를 만들고 반환된 ID를 새 항목에 붙여 목록 앞에 추가한다.

    두 작업 모두 성공하면 `true`를 반환해 폼이 목록으로 이동할 수 있게 한다.

  9. 97-107

    Firestore 저장이 실패하면 사용자에게 표시할 안내를 `error`에 넣고 `false`를 반환한다.

    `finally`는 등록·수정 성공과 실패 모두에서 `busy`를 끈다.

    의존성 배열 `[user]`는 저장 함수가 참조하는 로그인 사용자가 바뀌면 콜백도 새 사용자 값을 사용하게 한다.

  10. 109-122

    `remove(id)`는 진행 상태를 켜고 이전 저장·삭제 오류를 지운 뒤 해당 문서를 `deleteDoc`으로 삭제한다.

    삭제가 성공하면 같은 ID를 제외한 배열을 만들어 `items`를 갱신하고 `true`를 반환한다.

    삭제 실패 시 `error`를 남기고 `false`를 반환하므로 호출한 상세 화면은 이동하지 않을 수 있다.

    `finally`가 모든 결과에서 진행 상태를 끄며 빈 의존성 배열은 상태 setter만 쓰는 삭제 콜백을 재사용하게 한다.

  11. 124-125

    반환 객체가 기록 목록, 진행 상태, 조회·변경 오류, 등록·수정 함수, 삭제 함수를 `ItemsProvider`에 전달한다.

    `ItemsProvider`는 이 값을 한 번만 만들고 `Store` Context로 공유하므로 각 페이지가 Firebase 요청 상태를 따로 만들지 않는다.

  2. 4-5

    `ProtectedRoute`는 객체 구조 분해로 받은 `children`을 보호할 화면의 내용으로 취급하는 함수형 컴포넌트다.

    `useContext(Auth)`는 `Auth` 컨텍스트의 현재 값을 반환하고, 구조 분해한 `user`에 로그인한 사용자 정보 또는 인증되지 않은 상태가 담긴다.

    `user`가 참인 경우 `children`을 그대로 반환해 원래 보호된 화면을 렌더링한다.

    `user`가 거짓인 경우 콜론 뒤의 `section`을 반환해 로그인 안내 화면을 렌더링한다.

  4. 9-12

    `<p className="eyebrow">PROFILE</p>`는 `PROFILE`이라는 작은 분류 문구를 `eyebrow` 스타일의 문단으로 표시한다.

    `<h2>로그인이 필요해요.</h2>`는 사용자에게 보호된 내용을 보기 전에 로그인이 필요하다는 제목을 보여 준다.

    두 번째 `<p>`는 `내 기록과 프로필을 보려면 먼저 로그인해 주세요.`라는 구체적인 안내 문장을 렌더링한다.

줄별 설명

  1. 1-1

  2. 2-2

    `return (`은 컴포넌트가 렌더링할 JSX 값을 반환하기 시작한다. 괄호는 여러 줄에 걸친 JSX를 하나의 반환 표현식으로 묶는다.

  3. 3-3

    `<button>`은 실제 HTML 버튼 요소를 만든다.

    `className={...}`에서 JSX 중괄호는 JavaScript 표현식을 속성값으로 평가하게 한다. `"btn " + kind`는 공통 클래스 `btn` 뒤에 `kind` 값인 `primary` 같은 변형 이름을 붙여 `"btn primary"` 형태의 클래스 문자열을 만든다.

  4. 4-5

    `{children}`은 함수 인자로 받은 내용을 JSX 안에 삽입한다. 문자열, 아이콘, 다른 JSX 요소 등 호출자가 전달한 값이 버튼의 여는 태그와 닫는 태그 사이에 표시된다.

  5. 6-7

  • useItems가 사용자별 Firestore 조회와 등록·수정·삭제를 담당합니다.
  • 목록·로딩·오류 상태도 훅에서 갱신하고 ItemsProvider가 Context로 세 페이지에 공유합니다.
  • 목록 화면은 상태를 표시하고 데이터 요청은 훅이 맡아 평가 기준의 데이터 흐름 분리를 충족합니다.

줄별 설명

  1. 1-14

    `useCallback`, `useContext`, `useEffect`, `useState`는 사용자 정보와 비동기 요청 상태를 관리하는 React 훅이다.

    Firestore의 `getDocs`, `addDoc`, `updateDoc`, `deleteDoc`가 조회와 CRUD 요청을 맡고, `collection`, `query`, `where`, `doc`는 대상 문서와 사용자별 조회 조건을 만든다.

    `Auth`와 `db`를 가져와 로그인 사용자와 Firebase 인스턴스를 이 훅의 데이터 경로에 연결한다.

  2. 16-21

    `useItems()`는 사용자별 기록 상태를 한곳에서 관리하는 커스텀 훅이다.

    `useContext(Auth)`에서 현재 `user`를 얻고, `items`에는 조회 결과, `busy`에는 요청 진행 여부를 둔다.

    `error`는 저장·삭제 실패, `loadError`는 최초 목록 조회 실패를 따로 보관해 화면에서 원인을 구분한다.

  3. 23-33

    `useEffect`는 인증 사용자 `user`가 바뀔 때마다 목록 조회를 다시 수행한다.

    `active`는 이전 사용자 요청이 늦게 끝나 새 사용자 화면을 덮지 못하도록 effect의 유효성을 표시한다.

    로그인 사용자가 없으면 기록과 조회 오류를 비우고 로딩을 끝낸 뒤 cleanup 함수를 반환해 이 effect를 무효화한다.

  4. 35-38

    새 사용자 조회를 시작할 때 기존 목록을 비워 다른 사용자의 기록이 잠시 보이지 않게 한다.

    `busy`를 켜고 `loadError`를 지운 뒤 `getDocs`로 `items` 컬렉션을 조회한다.

    `where("userId", "==", user.uid)` 조건이 현재 로그인 사용자 소유의 문서만 요청한다.

  5. 39-50

    조회가 완료되어도 `active`가 false면 이전 사용자 응답을 무시한다.

    각 Firestore 문서에서 `id`와 저장 필드를 합쳐 React가 쓸 기록 객체를 만든다.

    Timestamp의 `toDate()` 결과를 한국 날짜 문자열로 바꾸고 값이 없으면 `최근`을 표시한다.

    변환된 배열을 `setItems`에 넣어 Context를 소비하는 화면이 새 목록으로 다시 렌더링된다.

  6. 51-61

    조회 실패는 유효한 effect에서만 `loadError`에 기록해 목록 화면의 오류 상태로 전달한다.

    요청이 끝나면 여전히 현재 사용자 요청일 때만 `busy`를 끈다.

    effect가 정리되거나 `user`가 바뀌면 `active`를 false로 바꾸고, 의존성 배열 `[user]`가 재조회 시점을 결정한다.

  7. 63-79

    `save(data)`는 등록과 수정을 하나의 비동기 동작으로 제공하며 `useCallback`이 현재 `user`에 맞는 함수를 유지한다.

    로그인 사용자가 없으면 `error`에 안내를 저장하고 실패값 `false`를 반환해 페이지가 성공 화면으로 이동하지 않게 한다.

    요청을 시작할 때 진행 상태와 이전 오류를 갱신한 뒤 저장할 제목·내용·분류·사용자 ID·서버 시각을 `payload`에 모은다.

  8. 80-96

    `data.id`가 있으면 `updateDoc`으로 기존 문서를 갱신하고, 성공 뒤 같은 ID의 로컬 항목을 새 입력값으로 교체한다.

    수정된 항목의 `updated` 표시는 방금 갱신된 값으로 바뀐다.

    ID가 없으면 `addDoc`으로 새 문서를 만들고 반환된 ID를 새 항목에 붙여 목록 앞에 추가한다.

    두 작업 모두 성공하면 `true`를 반환해 폼이 목록으로 이동할 수 있게 한다.

  9. 97-107

    Firestore 저장이 실패하면 사용자에게 표시할 안내를 `error`에 넣고 `false`를 반환한다.

    `finally`는 등록·수정 성공과 실패 모두에서 `busy`를 끈다.

    의존성 배열 `[user]`는 저장 함수가 참조하는 로그인 사용자가 바뀌면 콜백도 새 사용자 값을 사용하게 한다.

  10. 109-122

    `remove(id)`는 진행 상태를 켜고 이전 저장·삭제 오류를 지운 뒤 해당 문서를 `deleteDoc`으로 삭제한다.

    삭제가 성공하면 같은 ID를 제외한 배열을 만들어 `items`를 갱신하고 `true`를 반환한다.

    삭제 실패 시 `error`를 남기고 `false`를 반환하므로 호출한 상세 화면은 이동하지 않을 수 있다.

    `finally`가 모든 결과에서 진행 상태를 끄며 빈 의존성 배열은 상태 setter만 쓰는 삭제 콜백을 재사용하게 한다.

  11. 124-125

    반환 객체가 기록 목록, 진행 상태, 조회·변경 오류, 등록·수정 함수, 삭제 함수를 `ItemsProvider`에 전달한다.

    `ItemsProvider`는 이 값을 한 번만 만들고 `Store` Context로 공유하므로 각 페이지가 Firebase 요청 상태를 따로 만들지 않는다.

줄별 설명

  1. 1-3

    `import { initializeApp } from "firebase/app"`는 Firebase 앱 초기화 함수를 `firebase/app` 모듈에서 가져온다. 중괄호 안의 이름은 모듈이 제공하는 특정 export만 선택한다는 뜻이며, 이 함수가 뒤에서 설정 객체를 Firebase 앱 인스턴스로 변환한다.

    `getAuth`와 `GoogleAuthProvider`는 `firebase/auth`에서 가져온 인증 API다. `getAuth`는 초기화된 앱에 인증 서비스를 연결하고, `GoogleAuthProvider`는 Google 로그인에 사용할 제공자 객체를 생성한다.

    `getFirestore`는 `firebase/firestore`에서 가져온 Firestore 연결 함수다. 뒤에서 같은 Firebase 앱을 전달해 원격 문서 데이터베이스에 접근할 `db` 인스턴스를 만든다.

  2. 5-12

    `const firebaseConfig = { ... }`는 Firebase SDK가 어느 프로젝트에 연결할지 설명하는 객체를 만든다. `const`는 이 변수 이름이 다른 객체를 가리키도록 재할당하지 않겠다는 선언이다.

    `import.meta.env`는 Vite가 실행·빌드 환경에서 제공하는 환경 변수 모음이다. `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`를 각각 `apiKey`, `authDomain`, `projectId` 속성에 넣어 실제 설정값을 소스에 직접 적지 않고 프로젝트 식별과 인증 도메인 정보를 전달한다.

    `storageBucket`, `messagingSenderId`, `appId`도 각각 `VITE_FIREBASE_STORAGE_BUCKET`, `VITE_FIREBASE_MESSAGING_SENDER_ID`, `VITE_FIREBASE_APP_ID`에서 읽는다. 객체 속성명은 Firebase가 기대하는 설정 키이고, 오른쪽 값은 배포 환경마다 달라질 수 있는 입력값이다.

    마지막 속성 뒤의 쉼표와 `}`는 객체 리터럴의 끝을 표시한다. 결과적으로 `firebaseConfig` 하나에 Firebase 초기화에 필요한 여섯 환경 변수 값이 모인다.

  3. 13-16

    `export const app = initializeApp(firebaseConfig)`는 앞에서 모은 설정 객체를 `initializeApp`에 인자로 전달해 Firebase 앱 인스턴스를 만들고, `export`로 다른 모듈이 같은 `app`을 가져다 쓰게 한다.

  1. 1-14

    `useCallback`, `useContext`, `useEffect`, `useState`는 사용자 정보와 비동기 요청 상태를 관리하는 React 훅이다.

    Firestore의 `getDocs`, `addDoc`, `updateDoc`, `deleteDoc`가 조회와 CRUD 요청을 맡고, `collection`, `query`, `where`, `doc`는 대상 문서와 사용자별 조회 조건을 만든다.

    `Auth`와 `db`를 가져와 로그인 사용자와 Firebase 인스턴스를 이 훅의 데이터 경로에 연결한다.

  2. 16-21

    `useItems()`는 사용자별 기록 상태를 한곳에서 관리하는 커스텀 훅이다.

    `useContext(Auth)`에서 현재 `user`를 얻고, `items`에는 조회 결과, `busy`에는 요청 진행 여부를 둔다.

    `error`는 저장·삭제 실패, `loadError`는 최초 목록 조회 실패를 따로 보관해 화면에서 원인을 구분한다.

  3. 23-33

    `useEffect`는 인증 사용자 `user`가 바뀔 때마다 목록 조회를 다시 수행한다.

    `active`는 이전 사용자 요청이 늦게 끝나 새 사용자 화면을 덮지 못하도록 effect의 유효성을 표시한다.

    로그인 사용자가 없으면 기록과 조회 오류를 비우고 로딩을 끝낸 뒤 cleanup 함수를 반환해 이 effect를 무효화한다.

  4. 35-38

    새 사용자 조회를 시작할 때 기존 목록을 비워 다른 사용자의 기록이 잠시 보이지 않게 한다.

    `busy`를 켜고 `loadError`를 지운 뒤 `getDocs`로 `items` 컬렉션을 조회한다.

    `where("userId", "==", user.uid)` 조건이 현재 로그인 사용자 소유의 문서만 요청한다.

  5. 39-50

    조회가 완료되어도 `active`가 false면 이전 사용자 응답을 무시한다.

    각 Firestore 문서에서 `id`와 저장 필드를 합쳐 React가 쓸 기록 객체를 만든다.

    Timestamp의 `toDate()` 결과를 한국 날짜 문자열로 바꾸고 값이 없으면 `최근`을 표시한다.

    변환된 배열을 `setItems`에 넣어 Context를 소비하는 화면이 새 목록으로 다시 렌더링된다.

  6. 51-61

    조회 실패는 유효한 effect에서만 `loadError`에 기록해 목록 화면의 오류 상태로 전달한다.

    요청이 끝나면 여전히 현재 사용자 요청일 때만 `busy`를 끈다.

    effect가 정리되거나 `user`가 바뀌면 `active`를 false로 바꾸고, 의존성 배열 `[user]`가 재조회 시점을 결정한다.

  7. 63-79

    `save(data)`는 등록과 수정을 하나의 비동기 동작으로 제공하며 `useCallback`이 현재 `user`에 맞는 함수를 유지한다.

    로그인 사용자가 없으면 `error`에 안내를 저장하고 실패값 `false`를 반환해 페이지가 성공 화면으로 이동하지 않게 한다.

    요청을 시작할 때 진행 상태와 이전 오류를 갱신한 뒤 저장할 제목·내용·분류·사용자 ID·서버 시각을 `payload`에 모은다.

  8. 80-96

    `data.id`가 있으면 `updateDoc`으로 기존 문서를 갱신하고, 성공 뒤 같은 ID의 로컬 항목을 새 입력값으로 교체한다.

    수정된 항목의 `updated` 표시는 방금 갱신된 값으로 바뀐다.

    ID가 없으면 `addDoc`으로 새 문서를 만들고 반환된 ID를 새 항목에 붙여 목록 앞에 추가한다.

    두 작업 모두 성공하면 `true`를 반환해 폼이 목록으로 이동할 수 있게 한다.

  9. 97-107

    Firestore 저장이 실패하면 사용자에게 표시할 안내를 `error`에 넣고 `false`를 반환한다.

    `finally`는 등록·수정 성공과 실패 모두에서 `busy`를 끈다.

    의존성 배열 `[user]`는 저장 함수가 참조하는 로그인 사용자가 바뀌면 콜백도 새 사용자 값을 사용하게 한다.

  10. 109-122

    `remove(id)`는 진행 상태를 켜고 이전 저장·삭제 오류를 지운 뒤 해당 문서를 `deleteDoc`으로 삭제한다.

    삭제가 성공하면 같은 ID를 제외한 배열을 만들어 `items`를 갱신하고 `true`를 반환한다.

    삭제 실패 시 `error`를 남기고 `false`를 반환하므로 호출한 상세 화면은 이동하지 않을 수 있다.

    `finally`가 모든 결과에서 진행 상태를 끄며 빈 의존성 배열은 상태 setter만 쓰는 삭제 콜백을 재사용하게 한다.

  11. 124-125

    반환 객체가 기록 목록, 진행 상태, 조회·변경 오류, 등록·수정 함수, 삭제 함수를 `ItemsProvider`에 전달한다.

    `ItemsProvider`는 이 값을 한 번만 만들고 `Store` Context로 공유하므로 각 페이지가 Firebase 요청 상태를 따로 만들지 않는다.
